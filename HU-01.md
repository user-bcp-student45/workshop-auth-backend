# HU-01 - Token firmado con expiracion y claims minimos

## Veredicto
**Usable con ajustes.** La historia conecta seguridad, configuracion, testing y evidencia.

## Contexto
El servicio de autenticacion expone `POST /auth/login` y devuelve `token`, `expiresIn` y `user`. El token se firma con RS256 usando una clave privada provisionada mediante `AUTH_TOKEN_SIGNING_KEY_LOCATION`. La Requirements API valida la firma y requiere los claims `sub`, `groups`, `iat` y `exp`; debe exigir y validar tambien `client`.

## Ajustes necesarios
- Exigir los claims `sub`, `client`, `groups`, `iat` y `exp`; mantener `groups` para compatibilidad con la Requirements API.
- Permitir unicamente el cliente `angular-workshop`. El emisor debe validar el valor recibido en la solicitud y reflejarlo en el token.
- Exigir y validar `client` al consumir el JWT en la Requirements API; rechazar el token si el claim falta, no es una cadena no vacia o no coincide exactamente con `angular-workshop`.
- Comprobar que `expiresIn` coincide con `exp - now` usando una tolerancia documentada.
- Mantener RS256 y provisionar la clave privada fuera del repositorio; la Requirements API debe disponer de la clave pública correspondiente.
- Evitar logs del token y de las claves.

## Criterios de aceptacion
- Un token valido tiene firma RS256 verificable y contiene `sub`, `client`, `groups`, `iat` y `exp`.
- La Requirements API rechaza tokens sin `client`, con `client` vacio o de tipo distinto de cadena, y con un `client` no permitido.
- El unico valor permitido para `client` es `angular-workshop`; la Requirements API rechaza cualquier otro valor.
- `expiresIn` es coherente con `exp - now` dentro de la tolerancia definida.
- Login valido, credenciales invalidas y token expirado tienen pruebas.
- No se registran tokens, claves ni valores sensibles.
- La clave privada se configura fuera del repositorio y la clave pública correspondiente permite validar el token en la Requirements API.

## Evidencia esperada
- Documento generado por los Skills a partir de este archivo.
- Pruebas de firma RS256, claims, expiracion y errores de autenticacion.
- Configuracion documentada de `AUTH_TOKEN_SIGNING_KEY_LOCATION` y `AUTH_TOKEN_PUBLIC_KEY_LOCATION`.
- Pruebas de la Requirements API para `client` ausente, mal formado, permitido y no permitido.
- Evidencia de logs redactados.
