# HU-01 — Token de autenticación seguro

## Origen

- **H-03 — Token Base64 con secreto embebido** (Pendiente). Evidencia: `LegacyTokenUtil.java:8`, `LegacyTokenUtil.java:13-15`.
- **H-04 — Secreto hardcodeado** (Pendiente; se toma únicamente el hallazgo sobre el secreto del token, no el hallazgo de CORS). Evidencia: `LegacyTokenUtil.java:8`.

## Contexto

El token actual usa Base64, incluye un secreto en el código y no cuenta con firma ni claims estándar. Como resultado, su contenido es reversible y se puede alterar o falsificar. Además, el secreto de firma está versionado en el código fuente. El cambio se limita a esos hallazgos; debe conservarse el contrato de `POST /auth/login`.

## Ajustes necesarios

- Sustituir el token reversible sin firma por un token firmado que utilice claims estándar, incluida la expiración.
- Validar la firma y la expiración al verificar tokens, y rechazar tokens alterados o no válidos.
- Obtener el secreto de firma de configuración externa, no de un valor literal en el código fuente.
- Mantener el contrato existente de `POST /auth/login`.

## Criterios de aceptacion

- Una prueba automatizada comprueba que un token emitido tiene una firma verificable y claims estándar de identidad y expiración.
- Una prueba automatizada altera el token emitido y comprueba que la verificación lo rechaza.
- Una prueba automatizada verifica que un token expirado es rechazado.
- Una prueba de configuración comprueba que el firmador obtiene el secreto de una configuración externa de prueba; la revisión del código confirma que no hay un secreto de firma literal versionado.
- Las pruebas de `POST /auth/login` comprueban que el contrato existente de la respuesta se conserva.

## Evidencia esperada

- Salida de las pruebas automatizadas de emisión y validación de tokens, incluidos los casos de alteración y expiración.
- Salida de las pruebas de configuración y de caracterización del contrato de `POST /auth/login`.
- Referencia a la configuración externa usada en la prueba y comprobación del código fuente de que el secreto no está hardcodeado. No adjuntar ni registrar valores de tokens, secretos o credenciales.
